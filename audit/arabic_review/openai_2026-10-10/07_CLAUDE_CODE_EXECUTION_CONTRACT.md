# عقد تنفيذ مقيّد — إلى Claude Code بعد قبول Claude لسجل القرارات

هذا عقد تطبيق فقط. لا يجوز استخدامه وحده بدل سجل `ACCEPTED_EDIT_REGISTER.csv` الذي يصدره Claude بعد التحكيم.

1. افحص HEAD وبصمة Production Master الحالية وأذونات الفرع. امتنع عن التعديل إن اختلفت الحالات عن اعتماد المستخدم.
2. لكل سطر مقبول: تحقق من `selector + field + original_sha256`، ومن صف/معرف Master المطابق. أوقف السطر عند اختلاف حرفي؛ لا تعتمد fuzzy matching ولا regex replacement على النصوص العامة.
3. عدّل `authority/Yemen_Financial_Inclusion_Evidence_Master.xlsx` بالوسيلة المعتمدة في المستودع إن كان التعديل في معنى أو حقوق أو تسمية محكومة؛ ثم أعد توليد الإسقاطات بآلية المستودع. لا تجعل JSON أو `dist/` سلطة محررة.
4. التغييرات التي تمس مؤشّر Findex أو فترات الثقة أو حالة قائمة بنك أو شروط إعادة الاستخدام لا تُنفذ من تخمين؛ تتطلب سجل تحكيم وحجج مصدر أصلي وقرار تكافؤ EN–AR.
5. شغّل اختبار ثبات الأعداد بالرموز وبالكلمات، ونطاق المؤشر والوحدة والمجتمع/المقام/الفترة/الجغرافيا والمصدر والحالة، وفحص حقوق إعادة التوزيع وعدم تسرب withheld/internal. حافظ على روابط المصادر وسجلات الأدلة والقراءات ونظام التصحيح.
6. اختبر الوجهتين على هاتف 390px وحاسوب 1440px، و200% zoom، وRTL/Bidi للتواريخ والاختصارات، والتركيز بلوحة المفاتيح، والنسخ والطباعة مع القيد الجوهري، والبدائل النصية وحالات «غير معروف / لا يعني صفرًا».
7. اعرض `git diff` مشروحًا ومسارات الملفات وMaster SHA وكل اختبار مع PASS/FAIL والسبب. لا تدّعِ أن مصدرًا أصليًا أو متصفحًا حيًا فُحص إن لم يحدث.
8. اعمل في فرع معزول وبلا نشر أو merge إلى `main` حتى موافقة المالك. ملفات التدقيق لا تدخل الصفحات العامة، ولا تُكشف أسماء جلسات أو نسخ قديمة في المخرجات العامة.

**معيار القبول:** حفظ الحقيقة والحجج وحقوق المصادر، وتحسّن مفهوم لأول قراءة، وإمكان التعقب الكامل، وعدم خلق مصدر حقيقة ثانٍ.
