6A. PRODUCT NORTH STAR
----------------------------------------------------------------------

The Design recipient must understand that this is not a generic website.

It is a public evidence service that should enable:

UNDERSTAND → EXPLORE → VERIFY

and, for consequential evidence:

ANSWER → SCOPE → BOUNDARY → VERIFY

Design should aim for:

MAXIMUM INFORMATIONAL COMPLETENESS
WITH
MINIMUM SIMULTANEOUS COGNITIVE LOAD.

It must preserve complexity where complexity is truthful while preventing
the user from having to carry the whole evidence architecture at once.

The site should feel:

calm but powerful;

formal but not bureaucratic;

precise but not cold;

distinctive but not theatrical;

editorial but not magazine-like;

deep but not crowded;

7. MACHINE-OPERABLE DESIGN BEHAVIOUR
======================================================================

Ensure the future Design agent is not merely given goals but a WORKING LOOP.

Where not already present, the canonical Design brief should encode a
repeatable cycle equivalent to:

ORIENT
→ QUESTION
→ EXPLORE
→ CHALLENGE
→ DECIDE
→ PROTOTYPE
→ TEST
→ PERSIST
→ CONTINUE

For consequential Design decisions:

ORIENT
Read the relevant governed content, visual contract, route and current
implementation.

QUESTION
Identify:
- what is governed;
- what is free;
- what problem is actually being solved.

EXPLORE
Consider materially different solutions where the decision matters.

CHALLENGE
Use audience, evidence, Arabic, accessibility, mobile, source-owner,
anti-template and engineering lenses.

DECIDE
Choose and document the reason.

PROTOTYPE
Use actual governed content.

TEST
Use difficult states, not only ideal content.

PERSIST
Update Design decision record, coverage, Design debt and Code handoff.

CONTINUE
Proceed only when the gate's acceptance conditions are met.
